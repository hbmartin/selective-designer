# Resume unfinished automatic detection

Persist the detection intent and image atomically. Allocate image and write identities before starting the transaction. Retry the complete image-and-intent transaction at most three times after confirmed transient rollback, with 100 ms and 300 ms delays. Serialization failures, deadlocks, and lock failures are eligible; configuration and constraint failures are not. After an uncertain commit, make at most three reconciliation reads with the same delays. Only a matching image, immutable write identity, and image attributes prove success. An unavailable or inconclusive reconciliation preserves the original error and never repeats the uncertain write or dispatches work. Dispatch happens after commit and the editor can recover it independently. An interrupted request can leave an intent that the image owner can recover in the editor. A confirmed failure before queue invocation is immediately retryable. Once the queue is invoked, a rejected response does not establish whether the worker was queued. When queue acceptance is uncertain, give the worker two minutes to claim the attempt. A claimed attempt has 30 minutes to finish. The owner can retry after failure or expiry, and a delayed worker cannot publish for the replacement attempt.

Record progress with the resulting regions so a retry runs only unfinished work. Restarting the whole detection would spend more provider calls and could replace regions already used in the editor. A replacement attempt owns future writes while completed regions and manual regions keep their identities.

For a revised design, attempt the mood board copy before dispatch. A reported copy failure also releases detection. The first worker snapshots the categories when it prepares the run, so edits saved between dispatch and preparation are included. If the copy never reports back, the owner can retry after two minutes and freeze the categories saved at that point. A late copy cannot change that run's snapshot.

A concept is complete when all returned masks are saved, including when the provider returns zero masks. A definitive prompt rejection or invalid mask leaves a visible omission. HTTP errors, unexpected content types, timeouts, and oversize declarations in headers remain retryable. A malformed or non-HTTPS source and a response body verified to exceed the mask limit are definitive rejections. Cleanup is limited to fresh uploads that definitively never published because a database error can arrive after commit.

Older runs have no checkpoints. Their automatic region labels are the available evidence of completion, so retry may repeat a concept that returned no masks or whose regions were renamed.

Apply the additive migration before deploying the new worker. On an existing deployment, verify that legacy workers without run ownership checks have drained before enabling the new reclaim behavior. Keep the previous workflow entry points available for replay. A historical image without a detection record may have completed successfully, so it is not automatically retried.

Retain completed detection records until image deletion. Successful completion and completion with omissions are terminal even after their execution deadline expires. Repeated scheduling recognizes completion without warning or queueing; a missing intent for a newly written image remains a diagnostic. Historical images without a record stay idle. Existing workflow entry points and step signatures remain replayable, and legacy finalization retains any matching record.

Generated masks use atomic create-only storage writes. A conflict cannot overwrite an existing mask and provides no cleanup ownership. Cleanup requires confirmed creation by this execution and confirmed non-publication. Reference checks span all regions, including copied regions. Preserve objects when upload, publication, or reference lookup is uncertain. Anticipated source failures are typed outcomes; storage and persistence system failures remain errors with explicit publication certainty. Provider success and cost records describe performed provider work independently of later application failures.

Base-design reconciliation covers one server write invocation. Render publication also survives a later workflow invocation: each result and attempt has stable image and write identities. Save the render completion and output-image link in the same transaction as the image and intent, with the current attempt and provider request fenced by a row lock. A replay reuses the committed registration before polling or copying again and can dispatch its existing intent. Explicit Retry starts another attempt. Browser resubmission idempotency, historical orphan cleanup, and reconstruction of historical registrations remain outside this decision.

Transient mask source reads retry the same URL at most three times, with one- and three-second delays, a 20-second attempt limit, and a 60-second total budget. Network errors, timeouts, HTTP 408/429, and HTTP 5xx exhaust as source errors that guarantee no destination write was attempted and retain the original diagnostic. Workflow retries remain available and may repeat a paid SAM call. Interactive requests retain usable masks from other sources; an entirely failed response remains actionable. Malformed or insecure URLs and verified oversized bodies keep their existing permanent-rejection behavior.

Image and region writes share PostgreSQL failure classification. Confirmed serialization, deadlock, and lock failures permit rollback recovery; connection errors and statement-completion-unknown remain uncertain. Log reconciliation failures without replacing the original write error or exposing signed URLs and credentials. Reference checks remain mandatory for cleanup even before publication: a freshly created storage object can have an existing database reference.

Deploy the additive migration before a coordinated server and worker cutover. Drain older application processes before serving retained terminal records: older readers do not understand the completed phase. Rollbacks must retain support for that phase. No completed records are reconstructed for historical images.

Migration 0012 creates the region mask-key index using the transactional migrator. It blocks region writes until that transaction commits; use the coordinated rollout with workers drained. Do not add `CONCURRENTLY` to an immutable transactional migration. Online index-build support requires a separate deployment procedure and is outside this change.
