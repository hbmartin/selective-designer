# Host on Vercel with Workflow SDK

Use Vercel with Workflow SDK for durable rendering tasks; current official documentation supports the app's TanStack Start/Nitro setup. This reduces service and worker setup compared with a separate managed runner or an always-running queue worker, while accepting Vercel-specific deployment and execution constraints. Keep recipes, model attempts, costs and history in application-owned records, and isolate Workflow calls behind infrastructure/composition so the scheduler can be replaced.

The Nitro workflow host initializes telemetry independently of SSR, and both entry points isolate user context per request. Terminal unresolved diagnostics use one acknowledged attempt per sink with a five-second limit and a sanitized console fallback. Ordinary OTel batching uses a separate exporter. Workflows await diagnostic delivery within the deadline. Upload requests return the persistence error while Vercel retains diagnostic delivery with `waitUntil`. When the host cannot retain work, the request writes the fallback to console and returns. Diagnostic delivery never changes workflow results or accounting dispatch.
